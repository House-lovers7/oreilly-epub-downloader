# Game-Design Domain Checklist

> 由来: O'Reilly技術書からの蒸留カード（knowledge-base/cards/game-design/）。
> 各項目の詳細・出典は card_id で practices/antipatterns/tradeoffs.jsonl を引く。

## ベストプラクティス（適用を検討したか）

- [ ] **挑戦難易度はプレイヤーの熟達度に応じて動的に調整する（フロー理論）** (gd-p-001): 常に「達成可能でぎりぎり手応えがある」状態を保つよう難度を調整する
- [ ] **プレイセントリックな反復設計プロセス：目標設定→プロトタイプ→プレイテスト→評価を繰り返す** (gd-p-002): 制作着手前に機能でなく「プレイヤーに味わってほしい状況」としての体験ゴールを言語化する
- [ ] **コアループを最初に成立させる** (gd-p-003): 意図→行動→フィードバック→メンタルモデル更新のループを少なくとも1つ確立する
- [ ] **意味のある決定には対立（ルール・敵対者・他プレイヤー・資源制約）を設計する** (gd-p-004): 決定がプレイヤー/世界の状態を識別可能に変化させ、以後の選択肢を広げる／狭めるようにする
- [ ] **パズル/レベル設計はルール設計を優先し、フロー維持で難易度を段階づける** (gd-p-005): 良いルールセットは多数の良質なレベルを生むため、ルール設計に十分な労力を割く
- [ ] **レベルごとにメカニクスのサブセットを絞り込み、段階的に導入する** (gd-p-006): 各レベルが特定の側面にフォーカスするようメカニクスの提示範囲を制御する
- [ ] **新しい概念は孤立導入→難度上昇→組み合わせの順でシーケンスする** (gd-p-007): 単独導入→難度漸増→既習概念との組み合わせの順で新メカニクスを教える
- [ ] **ゲームバランスは階層的サブシステムごとに調整してから統合する** (gd-p-008): 支配戦略や一方的な有利/不利がないかを基準にバランスを評価する
- [ ] **メカニクスをストーリーやアートより先に固め、遊べる試作として検証する** (gd-p-009): コンセプト段階ではフォーマル要素（役割・目的・行動・対立・勝敗条件）を先に定義する
- [ ] **プレイヤー体験目標は感情語彙で具体的に記述する** (gd-p-010): デザインピラーが与えるべき感情・経験をチームで言語化しプレイテストで検証可能にする
- [ ] **エスカレーション系パターンで難度をプレイヤーの熟練度に自動適応させる** (gd-p-011): 挑戦漸増・複雑性漸増パターンで進捗と難度の正のフィードバックループを作る
- [ ] **アクション/フィードバックループは100〜250ミリ秒以内に収める** (gd-p-012): 100ms未満で即時、250msを超えると行動と結果の結びつきが失われる
- [ ] **相互排他的な代替タスクには常にバックアップ手段を残す** (gd-p-013): 詰み（unsolvable state）を防ぐため常時選択可能な手段を用意する
- [ ] **バランス調整はシミュレーションで検証し、変更は一つずつ大きく振る** (gd-p-014): 一変数ずつ変更し、人工プレイヤーのシミュレーションで統計的に比較する
- [ ] **外的報酬はプレイヤーが自然に取りたくなる行動と一致させる（Rewards Alignment）** (gd-p-015): 報酬経路が単線的だと他のメカニクスが無視されるため評価基準を多面的にする
- [ ] **ゲームの長さは勝敗条件の設計で調整する** (gd-p-016): 序盤の猶予期間と終盤の強制決着メカニズムで長さをコントロールする
- [ ] **ツールの本質的な特性は固定し、それ以外のつまみでバランスを取る** (gd-p-017): フィクション上のアイデンティティに不可欠な特性は変更せず、副次的な数値で調整する
- [ ] **バランス変更の是非は母集団の行動データで判断する** (gd-p-018): フォーラムの声高な少数意見に引きずられず分析データを優先する
- [ ] **エレガンス（1要素が複数の目的を果たすこと）で深みを作る** (gd-p-019): 要素数を増やす前に既存要素の役割を拡張できないか検討する

## アンチパターン（該当していないか）

- [ ] **外的報酬の連鎖だけに頼ると『グラインド』化し内発的動機を損なう** (gd-a-001): 明示的目標だけに依存し続けていないか確認する
- [ ] **結果が同じイリュージョナリーチョイスは意味のある決定にならない** (gd-a-002): 選択肢がプレイヤー/世界の状態に識別可能な影響を与えるか検証する
- [ ] **マルチプレイヤー設計で乖離した目標（divergent goals/griefing）への対策を怠らない** (gd-a-003): 公式勝利条件と実際に魅力的な副次行動の乖離を点検する
- [ ] **障害物のない『空っぽの通過区間』を作らない** (gd-a-004): 各区間に緊張・発見・驚きを生むメカニクスを意図的に配置する
- [ ] **メンタルモデル構築が破綻するとバーンアウトで離脱する** (gd-a-005): 「分かってきた」達成感が積み重なっているかをプレイテストで継続確認する
- [ ] **支配戦略があると選択のパズルが解かれ意味のある選択が消える** (gd-a-006): 特定の選択肢・戦略への収束をプレイテストで監視し発見したら拮抗させる
- [ ] **コンテンツトレッドミル：見た目だけの新コンテンツはプレイヤーをすぐ飽きさせる** (gd-a-007): 追加コンテンツが根底のメンタルモデルに新しい学びをもたらすか確認する
- [ ] **達成感を伴わない継続的動機付けだけの『強制機械』設計はプレイヤーズリモースを生む** (gd-a-008): 動機付けの強さと満足感（fulfillment）を別軸で評価する
- [ ] **ソースとシンクの管理を誤ると経済がインフレ・停滞・アービトラージで崩壊する** (gd-a-009): 供給と消費のバランス、アービトラージ経路の有無を点検する
- [ ] **トレーニングレベルを開発の最後に作ると最初の体験が最も雑になる** (gd-a-010): トレーニングレベルを最初に作る、またはゲーム全体を学習体験にする
- [ ] **動的難易度調整（DDA）は現実感の毀損・悪用・熟達の喜びの剥奪という代償を伴う** (gd-a-011): 隠さず導入するか、救済策の形式（装備追加等）を慎重に選ぶ

## トレードオフ（明示的に判断したか）

- [ ] **コンテンツ主導とシステム主導の設計トレードオフ** (gd-t-001): 物語重視ならコンテンツ主導、自由度重視ならシステム主導を選ぶ
- [ ] **パイディア（自由遊び）とルドゥス（構造化された目標志向）のどちらに寄せるか** (gd-t-002): 明確な勝利条件と戦略性重視ならludus側に寄せる
- [ ] **動的難易度調整（DDA）と固定ルール構造のトレードオフ** (gd-t-003): 常時フロー維持を狙うか、プレイヤーが押し返せる一貫した挑戦を残すかを選ぶ
- [ ] **感情表現：システム創発（低精度・高当事者性）とカットシーン演出（高精度・低当事者性）** (gd-t-004): 狙った感情を確実に届けたいかプレイヤーの主体性を優先するかで選ぶ
- [ ] **プレイスタイル強化：経験値方式（間接・柔軟）と行動直結方式（直接・一貫）** (gd-t-005): 育成の柔軟性か行動とのダイレクトな結合かを選ぶ
- [ ] **誰のスキル水準に合わせてバランスするか（トップ層 vs ロー/ミドル層）** (gd-t-006): 競技性重視ならトップ層、物語・体験重視ならロー/ミドル層に合わせる
- [ ] **対称ゲームと非対称ゲームのトレードオフ** (gd-t-007): 公平性・スキル比較を優先するか、現実模倣・探索の多様性を優先するかを選ぶ
- [ ] **推移的バランス（奇数グループのじゃんけん型）と非推移的バランス（コスト連動）** (gd-t-008): 要素グループ数が奇数かどうか、進行システムの有無で使い分ける
- [ ] **負のフィードバックループ（安定化）と正のフィードバックループ（加速・不安定化）** (gd-t-009): 均衡を保ちたい箇所と急展開を狙う箇所を意図的に切り分ける
- [ ] **速度と認知的努力のバランス（Crawfordの原則）** (gd-t-010): 思考負荷の高いタスクは低速/ターン制、低いタスクは高速にする
